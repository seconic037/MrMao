# 毛选思维引擎 — 设计规格说明书

> 一个基于毛泽东著作（毛选+文集+其他）的RAG问答系统，融合毛式方法论推理层，以Web聊天界面提供服务。
> 后续可扩展为API接口。

---

## 一、项目背景与目标

### 1.1 背景
用户拥有毛泽东选集（1-4卷）、毛泽东文集（8卷）及其他著作的PDF电子书，
希望构建一个智能体，不仅能回答"毛选里讲了什么"，还能运用毛选的思维方法（抓主要矛盾、主客分析法等）来分析和回答问题。

### 1.2 目标
- **首要目标**：构建一个Web聊天界面，用户可向AI提问，AI基于毛选原文+毛式思维框架回答
- **次要目标**：后续阶段可提供RESTful API接口，供其他应用集成
- **区分度**：区别于现有 `maoxuan-workbench`（项目分析工作台），这个产品是通用的毛选问答智能体

### 1.3 成功标准
1. 能准确检索并引用毛选/文集中的原文段落
2. 回答中体现毛选式的分析框架（抓主要矛盾、主客分析法等）
3. 用户可追溯到原文出处（卷名·篇名·写作时间）
4. Web界面交互流畅，响应及时

### 2.1 架构决策
| 决策 | 选择 | 理由 |
|---|---|---|
| 后端框架 | FastAPI | 异步性能好、天然API支持、Python生态 |
| 向量数据库 | ChromaDB | 本地运行零配置、支持hybrid检索 |
| 嵌入模型 | BAAI/bge-small-zh-v1.5（优先）或 text-embedding-3-small | 中文语义理解，前者可离线免费使用 |
| LLM | deepseek-chat 或 OpenAI API | 根据环境和预算选择；book-to-skill萃取需高质量LLM |
| 前端 | 纯HTML+CSS+JS 单页应用 | 轻量，无需构建工具链 |
| 知识萃取 | book-to-skill 方法论 | 从原著中提取框架/原则/方法/反面模式，构建推理层基础 |
| 推理层 | 基于萃取知识库 + RAG原文检索 | 知识库提供"怎么想"，RAG提供"原文怎么说" |

## 三、模块详细设计

### 3.0 知识萃取层 — book-to-skill（前置步骤）

在构建RAG系统之前，先用 book-to-skill 方法论对毛选全集进行知识萃取。
这一步是**一次性**的离线处理，输出结构化的知识库 Skill 文件。

#### 3.0.1 萃取方式
使用 `book-to-skill` 技能（或受其方法论启发的独立脚本）对PDF进行分析提取。
支持四种运行模式：完整转换、仅分析、从分析生成、更新合并。

#### 3.0.2 萃取的知识类型

| 类型 | 毛选中的对应 | 示例 |
|---|---|---|
| **框架（Framework）** | 核心体系/世界观 | 辩证唯物主义、历史唯物主义、马克思主义中国化 |
| **原则（Principles）** | 指导性规则 | 实事求是、独立自主、群众路线、为人民服务 |
| **技术方法（Techniques）** | 具体工作方法 | 调查研究方法、矛盾分析法、阶级分析法、整风方法 |
| **反面模式（Anti-patterns）** | 需要避免的错误 | 本本主义、经验主义、主观主义、教条主义、尾巴主义 |

#### 3.0.3 输出格式
标准 Skill 文件（markdown），结构如下：
```markdown
# 毛泽东选集 — 知识库
> 基于毛选1-4卷、文集1-8卷及其他著作萃取

## 核心框架
- 辩证唯物主义认识论：...
- 历史唯物主义社会分析：...

## 基本原则
- 实事求是：...
- 群众路线：...

## 工作方法
- 矛盾分析法：...
- 调查研究法：...

## 反面模式
- 教条主义：...
- 经验主义：...

## 出处索引
每一条知识都标注原始出处（卷·篇·写作时间）
```

#### 3.0.4 与下游的关系
- 萃取的知识库 → 注入 **推理层**，作为毛式分析的思维原材料
- 原始PDF → 继续走 **RAG管道**，用于精确的原文引用检索
- 两者结合：book-to-skill 提供"怎么想"，RAG 提供"原文怎么说"

---

### 3.1 离线数据处理模块（一次性）

#### 3.1.1 PDF解析（pipeline/pdf_parser.py）
- 工具：pymupdf (fitz)
- 输入：毛选1-4卷PDF、文集1-8卷PDF、其他著作PDF
- 输出：结构化文本，每篇包含：
  - `source`：来源（如"毛泽东选集 第一卷"）
  - `title`：篇名（如"实践论"）
  - `date`：写作日期（如"1937年7月"）
  - `content`：正文内容
  - `metadata`：原始文件信息
- 规则：按篇为天然提取单位，保留章节层级

#### 3.1.2 文本分块（pipeline/chunker.py）
- 策略：以「篇」为天然边界，超长篇按节/自然段落切割
- 块大小：500-1000 tokens（约750-1500中文字符）
- 块重叠：10%（保证上下文连续性）
- 每条块记录格式：
  ```json
  {
    "id": "mzq_v1_001_003",
    "text": "...",
    "source": "毛泽东选集 第一卷",
    "title": "实践论",
    "date": "1937年7月",
    "chunk_index": 3
  }
  ```

#### 3.1.3 向量化与入库（pipeline/embed_and_store.py）
- 将每个文本块转为向量
- 存入ChromaDB collection "maozedong-works"
- 保留全部元数据以供检索后展示

### 3.2 RAG检索层（rag/retriever.py）

#### 3.2.1 检索流程
1. 用户提问 → 生成问题向量
2. ChromaDB 向量相似度搜索（top-10）
3. BM25 关键词检索（top-5）
4. 合并去重，按相关性排序
5. 取 top-5 作为上下文

#### 3.2.2 输出格式
```python
[
  {
    "text": "原文段落...",
    "source": "毛泽东选集 第一卷",
    "title": "实践论",
    "date": "1937年7月",
    "score": 0.92
  },
  ...
]
```

### 3.3 毛式推理层（reasoning/）

推理层是系统的"大脑"，基于 book-to-skill 萃取的结构化知识库，
结合RAG检索到的原文，进行毛选式的分析推理。

#### 3.3.1 知识库基础
- 输入：book-to-skill 萃取的结构化知识库文件（框架/原则/方法/反面模式）
- 作为系统提示的一部分注入LLM，或作为向量知识库单独索引
- 保证每条知识都附带原始出处，便于交叉引用

#### 3.3.2 分析方法论
基于萃取的知识库，系统掌握的四大分析维度：

| 分析维度 | 萃取来源 | 适用场景 |
|---|---|---|
| 矛盾分析法 | 萃取自《矛盾论》 | 分析复杂问题，抓主要矛盾 |
| 主客分析法 | 萃取自《实践论》《论持久战》等 | 评估形势和可行性 |
| 调查研究法 | 萃取自《反对本本主义》《农村调查》 | 信息不足时指导如何获取信息 |
| 战略推演 | 萃取自《论持久战》《中国革命战争的战略问题》 | 规划/决策的多路线推演 |

#### 3.3.2 Prompt模板（reasoning/prompts/）
- `qa_with_reasoning.jinja2`：结合检索原文+推理框架的问答模板
- `pure_reasoning.jinja2`：无原文但有毛式分析的问题模板
- 结构化输出的格式指令

### 3.4 Web服务（web/）

#### 3.4.1 后端（web/app.py）
- FastAPI 应用
- 端点：
  - `POST /api/chat` — 单轮问答（主要端点）
  - `POST /api/chat/stream` — 流式输出（可选）
  - `GET /api/sources` — 列出已入库的文献清单
  - `GET /api/status` — 系统状态
- 请求体：`{"message": "问题", "session_id": "可选"}`
- 响应体：`{"answer": "回答", "sources": [...引用出处...], "thinking": "推理过程（可选）"}`

#### 3.4.2 前端（web/static/）
- 单页HTML应用（index.html）
- 仿聊天界面布局
- 特性：
  - 消息气泡（用户/助理）
  - 引用出处脚注显示
  - 可点击展开查看原文
  - 打字机效果流式展示
  - 响应式设计（PC+移动端）

### 3.5 会话管理
- 当前阶段：内存暂存（Python dict）
- 后续阶段可升级为Redis或SQLite持久化
- 保留最近N轮对话历史，供推理层参考上下文

## 四、用户问答完整流程

以「如何看待当前创业环境？」为例：

1. **用户输入** → FastAPI 接收 `POST /api/chat {"message": "如何看待当前创业环境？"}`
2. **推理层初始化** → 加载 book-to-skill 萃取的结构化知识库，识别适用的分析维度
3. **RAG检索原文** → 从ChromaDB召回最相关段落：
   - 《实践论》：认识来源于实践
   - 《矛盾论》：主要矛盾分析
   - 《论持久战》：敌我力量对比
   - 《反对本本主义》：调查研究
4. **知识库增强** → 从萃取的知识库中提取相关的方法论指导：
   - 矛盾分析法框架 → 判断主要矛盾
   - 调查研究方法 → 如何获取真实情况
5. **毛式推理层分析** → 结合知识库方法论 + 原文段落：
   - 抓主要矛盾：当前创业的主要矛盾是什么？
   - 主客分析：客观（政策/市场/资本）+ 主观（创业者能力）
   - 实事求是：引用原文中的具体指导
6. **回答生成** → 结构化输出：
   > **根据《矛盾论》(1937)的分析方法**，当前创业环境的主要矛盾是……
   > **毛主席在《论持久战》(1938)中强调**战略持久战……
   > **结合"没有调查就没有发言权"(《反对本本主义》，1930)**……
   > **建议**：① 调查研究先行 ② 集中优势兵力 ③ ……
5. **前端展示** → 消息气泡 + 出处脚注

## 六、关键技术决策

### 6.1 RAG vs 纯Prompt
选择RAG。文献量极大（毛选4卷+文集8卷≈300万字），远超任何模型上下文窗口。
RAG是唯一可行的精确检索方案。

### 6.2 本地 vs API模型
- 嵌入模型：优先选BAAI/bge-small-zh-v1.5（本地运行，免费，中文优化）
- LLM：优先用API（OpenAI/deepseek），效果稳定。后续可切换到本地大模型
- book-to-skill 萃取步骤需要一个高质量的LLM（OpenAI或deepseek）来保证分析质量

### 6.3 向量数据库选型
ChromaDB vs Qdrant vs Milvus：
- ChromaDB：零配置，单文件存储，适合原型和小规模部署
- 本项目先上ChromaDB，数据量大时可迁移

### 6.4 推理层方案：book-to-skill 知识萃取 vs 直接Prompt
选择 **book-to-skill 知识萃取** 方式：
- 先用 book-to-skill 方法论从全集中提取框架/原则/方法/反面模式
- 将萃取结果作为结构化知识库注入推理层
- 优点：知识密度高、避免每次推理都从原文检索、可独立迭代更新
- RAG 仍然保留，但职责缩小为"精确原文引用和出处验证"

### 6.5 与 maoxuan-workbench 的关系
- 本次项目以 **book-to-skill 萃取的知识库** 为推理层基础
- maoxuan-workbench 的项目分析方法论作为可选补充
- 两者不冲突，萃取结果也可被 maoxuan-workbench 使用

## 七、阶段规划

### 第一阶段：知识萃取 + MVP（当前实现）
- **book-to-skill 知识萃取**：对毛选1-4卷进行框架/原则/方法/反面模式提取

- 基础RAG问答（基于萃取知识库 + 原文检索）

- 支持毛选1-4卷

- book-to-skill 增量萃取：加入毛泽东文集8卷
- 混合检索（向量+关键词）

- 引用脚注可交互

### 第三阶段：扩展
- 所有著作全量知识萃取
- RESTful API
- 会话持久化
- 更多推理框架（如战略推演）

## 九、与maoxuan-workbench的关系

| 维度 | maoxuan-workbench（现有） | 毛选思维引擎（本项目） |
|---|---|---|
| 定位 | 项目分析工作台 | 通用毛选问答智能体 |
