# 知识库桌面编辑器 — 设计规格

> 日期：2026-08-01 ｜ 分支会话：知识库编辑器
> 关联 handoff：`docs/handoffs/2026-08-01-kb-editor.md`
> 状态：已获用户认可（2026-08-01）

## 1. 背景与目标

将现有**单向**"归并新知识"功能（`新知识放这里/归并新知识.bat` + `tools/ingest_knowledge.py`）升级为**知识库文件管理**能力：用户通过一个独立桌面编辑器，查看知识库文件清单、检索定位相关文件、按文件为最小单位增删，并在语料库变更后重建向量库、框架层变更后重启服务。

**与 handoff 原始需求的差异（经用户多轮澄清收缩）：**

| 原始需求 | 最终决定 |
|---------|---------|
| Web 页内编辑器（阅读页入口 + 管理员口令） | **独立 Tkinter 桌面应用**（本机专用，无需口令） |
| 查看/编辑全文 | **不做全文查看/编辑**，文件为最小操作单位，只显示文件名 + 元信息 |
| 检索返回 chunk + 来源 | 检索只返回**命中文件列表（文件名 + 命中数）**，不展示正文 |
| 文件树 + 编辑区 + 检索结果区 | 分栏：左侧文件树 + 右侧操作面板 |
| — | 新增：删除走**软删除**（备份到 `新知识放这里/_已删除/`） |

**服务器就是本机**：编辑器直接操作项目目录文件，无需远程同步。

## 2. 范围

### 包含

- 文件树展示：框架层 `knowledge/framework/*.md` + 语料库 `data/txt/知识扩展/*.txt`（文件名、大小、只读标记）
- 关键词检索：返回命中文件列表（文件名 + 命中行数，降序）
- 新建文件：类型（框架 .md / 语料 .txt）+ 文件名 + 内容粘贴，一次性创建
- 删除文件：二次确认 + 软删除（移动到 `新知识放这里/_已删除/`）
- 重建向量库：后台运行 `python run_pipeline.py`，stdout 实时滚动显示进度
- 重启服务：检测 nssm 服务，存在则提供重启按钮；否则提示手动重启
- 生效机制提示：框架层变更 → 重启服务；语料库变更 → 重建向量库

### 不包含（明确排除）

- 不做全文查看、不做全文编辑/保存
- 不重命名文件
- 不修改 RAG/think 核心、日志系统、考考你题库
- 不推送 GitHub
- 不扫描 `data/chroma_*`、`data/extracted`、`聊天记录/`、`tools/nssm`、`.env`
- `_全文.txt` 卷本与 >1MB 超大文件只读（不可删除）

## 3. 架构

### 3.1 形态

- 新文件 `tools/kb_editor.py`：**单文件 Tkinter 应用**（Python 3.11 标准库，零第三方依赖），风格参考 `tools/ingest_knowledge.py`（UTF-8 控制台、`pathlib` 路径处理）
- 启动方式：
  - `python tools/kb_editor.py`
  - 新增 `知识库编辑器.bat` 置于项目根，双击启动（含 `cd /d %~dp0` + UTF-8 代码页设置）

### 3.2 目录常量

```python
ROOT = Path(__file__).parent.parent
MD_DIR = ROOT / "knowledge" / "framework"
TXT_DIR = ROOT / "data" / "txt" / "知识扩展"
TRASH_DIR = ROOT / "新知识放这里" / "_已删除"
PIPELINE_CMD = ["python", "run_pipeline.py"]
```

### 3.3 只读规则

- 文件名以 `_全文.txt` 结尾 → 🔒 只读
- 文件大小 > 1MB → 🔒 只读（如《国富论》2.4MB、《经济学原理》193KB 以下正常）
- 只读文件：删除按钮禁用，树节点显示 🔒 标记

## 5. 功能细节

### 5.1 检索

- 遍历 `MD_DIR/*.md` 与 `TXT_DIR/*.txt`（即框架层 + 知识扩展；卷本全文在 `data/txt/毛选第一卷/` 等独立目录，不在编辑器管理范围，不参与检索）
- 逐文件按 UTF-8 读取，按行统计关键词出现次数（`line.count(query)`），命中行数 > 0 的文件进入结果
- 结果按命中数降序，显示 `文件名 (N处)`
- 命中列表点击 → 在状态栏显示"位于 xxx 目录，共 N 处"（不打开正文）

### 5.2 新建

- 表单：类型下拉（🧠 框架 .md / 📖 语料 .txt）+ 文件名输入 + 内容多行输入
- 校验（全部通过才创建）：
  - 文件名非空、无扩展名则按类型自动补 `.md` / `.txt`
  - 扩展名必须匹配类型（`.md` ↔ 框架，`.txt` ↔ 语料）
  - 文件名不含 `/\:*?"<>|` 与 `..`（防路径穿越）
  - 目标目录中无重名
- 创建：UTF-8 写入；成功后刷新文件树 + 状态栏提示生效机制
- 语料库新建 → 提示"需重建向量库"；框架新建 → 提示"重启服务后生效"

### 5.3 删除（软删除）

- 选中文件（仅非只读）→ [删除] → 确认弹窗（`messagebox.askyesno`，显示文件名）
- 确认后 `shutil.move` 到 `TRASH_DIR / filename`（同名则追加时间戳后缀）
- 刷新文件树 + 提示生效机制
- 不提供"恢复"按钮（用户可在文件系统手动移回）；状态栏提示备份路径

### 5.4 重建向量库

- 按钮 [重建向量库]：`subprocess.Popen(["python", "run_pipeline.py"], stdout=PIPE, stderr=STDOUT, text=True, encoding="utf-8", cwd=ROOT)`
- 子线程逐行读 stdout → 主线程滚动追加到进度区（`Text` 组件，只读）
- 运行中按钮置灰禁用（互斥）；完成/失败通过 `returncode` 判断并提示
- 重建期间允许其他操作（检索/新建/删除不依赖向量库）

### 5.5 重启服务

- 启动时探测 nssm 服务：对候选服务名列表 `["MrMao", "mrmao", "ChairManMao", "chairmanmao"]` 依次执行 `sc query <名>`，首个返回 RUNNING 的即命中；全部未命中则服务不存在
- 服务存在 → 顶栏 [重启服务] 按钮可用：`nssm restart <服务名>`（用 `tools/nssm/nssm-2.24/win64/nssm.exe` 绝对路径）
- 服务不存在 → 按钮灰置，状态栏提示"请手动重启：python run_server.py"

## 6. 生效机制（两套，UI 明确区分）

| 层 | 变更操作 | 生效方式 | GUI 提示 |
|----|---------|---------|---------|
| 框架层 `knowledge/framework/*.md` | 新建 / 删除 | **重启服务**（think prompt 每轮注入，改后即生效） | 提示 + 重启按钮 |
| 语料库 `data/txt/知识扩展/*.txt` | 新建 / 删除 | **重建向量库**（run_pipeline.py，3-10 分钟） | 提示 + 重建按钮 |

## 7. 安全与错误处理

- 文件名白名单校验（见 5.2），拒绝路径穿越
- 所有文件读写 UTF-8；控制台 `sys.stdout.reconfigure(encoding="utf-8")`（参考 ingest 的 GBK 处理）
- 重建任务互斥；Popen 失败（找不到 python/管道报错）→ 状态栏错误提示
- 文件读取失败（编码异常等）→ 单文件跳过并在状态栏列出，不中断整体
- 删除走软删除（可恢复），不直接删除文件

## 8. 测试

项目无测试套件（无 pytest 配置）。验证方式：

- 手工验收清单（启动 GUI、检索、新建、删除、只读禁用、重建进度）
- 纯逻辑函数（`validate_filename`、`count_hits`、`classify`）写成模块级函数，可用 `python -c` 快速冒烟验证
