# 规格：MrMao 知识库工作流编辑器 v2

> 2026-08-01 · 基于 handoff `docs/handoffs/2026-08-01-kb-editor-v2.md` · 用户确认设计后固化为本文档
>
> **实现状态：✅ 已合入 master（提交 `7006087`）**。24 项 unittest + GUI 冒烟全部通过。已知偏差：§10「落盘前 stat 校验并发修改」未实现（计划亦未覆盖，单用户工具风险极低）；§10「重建失败允许重试」实现为更保守的「禁用上传按钮 + 提示手动运行 run_pipeline.py」（语料已落盘、源文件已归档，重传会 FileNotFoundError）。

## 1. 任务目标

重做 `tools/kb_editor.py`（v1：414 行散装文件管理），改为**工作流驱动的知识库编辑器**：把现有命令行流程（丢文件进 `新知识放这里/` → `python tools/ingest_knowledge.py` → 重建向量库/重启服务）可视化为四步向导 + 独立知识库浏览页，全程**草稿清单先行、确认后落盘**。

**核心矛盾解决**：v1"不会用"是因为它是功能堆砌（检索/新建/删除/重建/重启各管各），不是用户心智中的"检索新知识→分类→编辑清单→合并更改→同步→上传→重启"线性流程。

## 2. 背景与现状（已核实）

| 项 | 现状 |
|----|------|
| 新知识入口 | `新知识放这里/`：README.md、NPC知识库情况.md、归并新知识.bat、5 个待归并 md（01-哲学方法论…05-反面模式）、2 个 BTS 蒸馏 md、`_已处理/`、`_已删除/` |
| 归类逻辑 | `tools/ingest_knowledge.py`：`.txt`→复制到 `data/txt/知识扩展/`；`.md`→按 `TOPIC_RULES` 关键词推断主题，目标文件存在则**追加合并**否则新建；处理后原文件移入 `_已处理/` |
| 生效机制 | 框架层（`knowledge/framework/*.md`）→ 重启服务；语料库（`data/txt/知识扩展/*.txt`）→ 重建向量库（`run_pipeline.py`，3-10 分钟） |
| 服务器状态 | nssm 服务 `MrMao` 存在但 **STOPPED**；8000 端口实际由**前台 python 进程**（uv 管理 Python 3.11）监听 → v1 的 `nssm restart` 按钮实际失效 |
| 启动入口 | `知识库编辑器.bat` → `python tools/kb_editor.py`（保持不动） |
| 重复风险 | `新知识放这里/经济学原理_Marshall_BTS.md` 与语料库 `经济学原理_Marshall_ST` 等高度疑似重复 → 去重检测是真实需求 |

## 3. 已确认需求（ask 决策记录）

1. **应用形态**：Tkinter + 双击 bat 启动，不打包 exe
2. **"检索是否是新知识"**：扫描发现新文件 + **去重检测**（文件名/内容比对）+ **自动分类**（.md→框架、.txt→语料）
3. **状态模型**：两级状态——本次更改清单是草稿（**落盘前磁盘文件一律不动**，可撤销）；点"开始上传"才真正写盘
4. **生效处理**：自动判断引导——仅框架改动→重启服务；含语料库改动→重建向量库 + 重启服务
5. **清单编辑能力**：从清单移除、调整分类目标（.md 可选"合并到已有主题文件/新建独立文件"）、只读预览内容；**不提供内容编辑**

## 5. 工作流四步

### ① 新知识（检索新知识）

- 「🔄 刷新资料库」：扫描 `新知识放这里/` 顶层 `*.txt` / `*.md`，排除 `AUTO_GENERATED = {"README.md", "NPC知识库情况.md"}` 与 `_已处理/`、`_已删除/` 子目录
- 每文件检测三项（表格/列表行展示）：
  - **分类**：`.md → 🧠 框架`、`.txt → 📖 语料库`
  - **去重检测**：文件名主干比对（如 `经济学原理_Marshall_BTS` vs 库内 `经济学原理_Marshall_ST` 主干相同）+ 内容首 500 字与库内同名/同主干文件比对，命中标 `⚠️ 疑似重复`（不阻断，仅警示）
  - **状态**：待处理
- 行操作：移除（本次不处理）、双击只读预览
- 提示区：引导文案"把 TXT/MD 丢进 `新知识放这里/` 文件夹后点刷新"
- 有文件时启用「下一步 →」进入 ②

### ② 待上传清单（编辑待上传清单）

- 展示 ① 确认的文件（未被移除者）
- 每行：文件名 + 大小 + 分类目标下拉框：
  - `.md`：目标 = 按 `TOPIC_RULES` 推断的主题文件（如 `经济学.md`），下拉可选「合并到 经济学.md / 哲学.md / 历史.md / 兵法战略.md / 文学.md / 科学.md / 新建独立文件」
  - `.txt`：固定 `data/txt/知识扩展/`（禁改）
- 行操作：移除、双击只读预览
- 「← 上一步」「下一步 →」

### ③ 本次更改清单（合并入本次更改清单）

- 上半：**新增** = ② 清单（N 项）
- 下半：**删除** = 知识库页标记的文件（M 项；🔒 只读文件不可标记）
- 总览文案：本次共新增 N / 删除 M
- 纯草稿：此阶段不触碰磁盘任何文件
- 「← 上一步」「下一步 →」（有任一改动才可进入 ④）

### ④ 同步与生效（决定上传 → 重启服务器）

- 差异总览：将写入的文件（含合并目标）、将删除的文件
- 「▶ 开始上传」点击后才**落盘**，执行顺序：
  1. `.md` → 复制或合并进 `knowledge/framework/`（目标文件存在则追加 `\n\n---\n` + 内容；否则新建）
  2. `.txt` → 复制进 `data/txt/知识扩展/`
  3. 删除文件 → 移入 `新知识放这里/_已删除/`（软删除，同名加时间戳）
  4. 已处理新文件原文件 → 移入 `新知识放这里/_已处理/`
  - **原子性**：先全部复制/预检到临时位置，全部成功后才执行移动；任一步失败 → 回滚已移动项 + 日志提示
- 生效自动判断：
  - 仅框架改动 → 提示「重启服务器」→ 执行重启（见 §7）
  - 含语料库改动 → 提示「重建向量库（3-10 分钟）」→ 日志实时回灌 → 成功后重启服务
- 日志区（只读 Text）：上传步骤、重建进度、重启结果逐行追加
- 完成横幅/提示：**"✅ NPC 已拥有新思想"**

## 6. 知识库页

- 左侧 Treeview 两棵树（按需展开）：
  - 🧠 框架层 `knowledge/framework/`（`*.md`，标注"重启服务生效"）
  - 📖 语料库 `data/txt/知识扩展/`（`*.txt`，标注"重建向量库生效"）
  - 每项：文件名 + 大小 + 🔒 只读标记（`_全文.txt` 结尾或 >1MB）
- 右侧：文件内容**只读预览**（`tk.Text` 设 `state=DISABLED`，UTF-8 读取失败则提示）
- 顶部工具行：
  - 关键词检索框 + 检索按钮：搜全库（复用 v1 `search_files` 逻辑），结果列表双击定位文件并在预览区打开
  - 「🗑 标记删除」：加入 ③ 的删除清单（只读文件拒绝并提示）；已标记文件在树中显示 `🚫` 前缀，可取消标记
- 树/预览在 `工作流` 向导切换时保持状态

## 7. 服务器重启与状态检测

- **状态灯**：`socket.connect(("127.0.0.1", 8000))` 探测；🟢 运行中 / 🔴 未运行（`after` 每 30s 轮询）
- **重启逻辑**（`restart_server()`）：
  1. 若有 nssm 服务在跑（`sc query` 候选名 `RUNNING`）→ `nssm restart <name>`
  2. 否则：查找 8000 端口 PID（`netstat -ano`）→ `taskkill /PID <pid> /F` → `subprocess.Popen(["python", "run_server.py"], cwd=ROOT, creationflags=CREATE_NO_WINDOW)` 后台重启
  3. 等待端口恢复（最多 30s 轮询）→ 状态灯变绿
- 杀进程/重启前需弹确认框（属系统级操作）；软删除无需确认（可恢复）

## 8. 技术要点

- 保留 Tkinter / ttk，零第三方依赖（Python 3.11 标准库），`知识库编辑器.bat` 入口不变
- `TOPIC_RULES` 与 `AUTO_GENERATED` 从 `ingest_knowledge.py` 抽取为共享常量（放 `tools/kb_editor.py` 内，ingest 保持不变或引用——**优先不动 ingest_knowledge.py**，在编辑器内复制常量并注释来源，避免破坏现有命令行工具）
- v1 保留能力：关键词检索、软删除、只读保护、重建向量库、关窗保护（重建中 terminate 子进程）
- 所有文件 UTF-8；不扫 `data/chroma_*`、`data/extracted`、`聊天记录/`、`.env`、`tools/nssm`
- 中文注释，类/函数用英文名

## 9. 数据流

```
用户拖文件进 新知识放这里/  →  ①刷新：扫描+去重+分类  →  ②待上传清单(可调目标)
→  ③本次更改清单(新增+删除草稿,磁盘不动)  →  ④开始上传: 原子落盘
→  自动判断: 仅框架→重启 / 含语料→重建向量库+重启  →  NPC 生效
```

## 10. 错误处理

| 场景 | 处理 |
|------|------|
| 文件读取失败（编码） | 预览区提示"无法读取"，清单仍显示 |
| 落盘中途失败 | 回滚已移动项，日志红字提示，清单状态不推进 |
| 重建向量库失败（退出码非 0） | 日志提示查看上方输出，允许重试 |
| 8000 端口杀不掉/起不来 | 日志提示手动处理：`python run_server.py` |
| 目标主题文件被并发修改 | 落盘前重新 stat 校验，冲突则提示重试 |

## 11. 范围（明确不做）

- ❌ 不提供文件内容编辑（只读浏览，用户明确不需要）
- ❌ 不打包 exe、不改启动入口
- ❌ 不改 RAG/think 核心、日志系统、考考你题库、`web/` 前端
- ❌ 不推 GitHub（除非用户明确说）
- ❌ 不自动删除 `_已处理/`、`_已删除/` 历史归档

## 12. 成功标准

1. 双击 `知识库编辑器.bat` 打开即可用，四个步骤按顺序走完，无需命令行
2. 新文件丢进 `新知识放这里/` 后，刷新可见、去重警示可见、分类目标可调
3. 上传前磁盘零改动；点上传后文件按规则落盘并可回滚
4. 生效方式自动判断：框架改动重启即生效、语料改动重建向量库后生效
5. 完成提示"NPC 已拥有新思想"，服务器状态灯与实际一致
