# ai-diary: AI自媒体日记助手 — 设计规格

## 概述

创建一个 Reasonix Skill `ai-diary`，自动记录用户与 AI Agent（Reasonix + DeepSeek）的交互过程，生成多平台适配的自媒体内容。

**定位：** 日记型自媒体 — 「我和AI的日常」
**目标平台：** 全平台同步分发（小红书/B站/抖音/公众号）
**AI工具：** Reasonix Agent + DeepSeek 模型

---

## 一、整体架构

```
┌─ 采集层 ─────────────────────────┐
│  对话结束时自动提取关键信息写入日志    │
│  (任务、工具调用、产出、评价)         │
└──────────────┬───────────────────┘
               ↓
┌─ 加工层 ─────────────────────────┐
│  /diary           → 查看摘要       │
│  /diary today     → 生成今日日记   │
│  /diary weekly    → 生成周报       │
│  /diary list      → 浏览历史       │
│  /diary endday    → 下班整合指令   │
│  + domestic-reach 辅助选题判断      │
└──────────────┬───────────────────┘
               ↓
┌─ 分发层 ─────────────────────────┐
│  /diary publish → 输出多平台适配版本 │
│  小红书(图文) / B站(脚本) / 公众号(文)│
└──────────────────────────────────┘
```

---

## 二、目录结构

产出内容统一存放在项目 `diary/` 目录下：

```
diary/
├── 2026-07-31.md              # 单日日记
├── 2026-08-01.md
├── weekly/                     # 周报
│   └── 2026-W31.md
└── drafts/                     # 待发布的草稿
    ├── xiaohongshu/            # 小红书适配版
    ├── bilibili/               # B站脚本版
    └── wechat/                 # 公众号长文版
```

## 三、日记条目结构

每条日记包含以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| 日期 | ISO格式 | 2026-07-31 |
| 标题 | 一句话概括 | 「用AI分析了今天的热点选题」 |
| 任务描述 | 用户让我做了什么 | 采集国内科技热点并生成选题报告 |
| 工具调用 | 用到的MCP/技能 | hotnews-mcp, domestic-reach |
| 关键产出 | 生成了什么 | 10条跨平台选题报告 |
| AI评价 | 从AI视角看这件事的价值 | 「这次分析发现了小米澎程系列的热度覆盖面很广，适合多平台创作」 |
| 适合平台 | 标注适合发的平台 | 小红书/公众号 |

## 四、命令接口

| 命令 | 功能 | 触发方式 |
|------|------|---------|
| `/diary` | 查看最近日记摘要 | 用户主动调用 |
| `/diary today` | 生成今日日记草稿 | 用户主动调用 |
| `/diary weekly` | 生成本周周报 | 用户主动调用 |
| `/diary list` | 浏览历史日记列表 | 用户主动调用 |
| `/diary publish` | 输出多平台适配版本 | 用户主动调用 |
| `/diary endday` | 生成当日摘要+结束记录 | 整合进「下班」指令 |

## 五、多平台输出适配

### 小红书（图文笔记）
- 标题：吸引眼球的提问/观点式，含 emoji
- 正文：800-1500字，口语化，分点列举
- 配图建议：截图/结果展示
- 格式：Markdown → 小红书友好格式

### B站/抖音（视频脚本）
- 时长：3-5分钟
- 结构：Hook开场(15s) → 问题引入 → 操作展示 → 结果呈现 → 总结
- 分镜/口播稿格式
- 核心：展示"AI怎么做"的过程

### 公众号（长文）
- 完整文章结构：标题→导语→正文（小标题分段）→总结
- 可以加入深度思考和背景介绍
- 2000-4000字
- 适合分享AI使用心得和方法论

## 六、整合现有流程

### 「下班」指令整合
- 在用户现有的"下班"流程末尾加入 `/diary endday`
- 自动生成当日日记摘要，追加到 `diary/YYYY-MM-DD.md`
- 如果有特别值得发布的内容，提醒用户

### 与 domestic-reach 联动
- 在 `/diary publish` 时，可调用 domestic-reach 判断当前日记话题的热度
- 辅助判断：这条内容是否值得发？适合发哪个平台？

---

## 七、采集方式

**自动化 + 手动结合：**

1. **自动采集** — 每次对话结束时，Reasonix 自动提取本次会话的关键信息（任务、工具、产出）
2. **手动精选** — 用户通过 `/diary today` 查看自动生成的草稿，修改润色后确认
3. **发布决策** — 用户决定哪些内容发布、发哪个平台

---

## 八、非功能需求

- 日记文件为纯 Markdown，可被任何编辑器打开
- 不依赖外部服务，所有数据本地存储
- 轻量级，不影响 Reasonix 正常使用
- 初次使用零配置，即装即用
