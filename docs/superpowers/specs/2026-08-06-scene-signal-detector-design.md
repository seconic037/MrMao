## 1. 设计目标

把手册 v4 第 7~11 层（冲突/幽默/拒绝/沉默/情绪爆发）和性格层（10 特质×激活情境）**一起实现进系统**，共享一个"场景信号检测器"。核心原则（G3）：不赌 LLM 自觉，规则粗判 + LLM 精修。

## 1.1 唤醒度维度（S6，并入本检测器轮）

**四象限**（Russell 情绪环状模型第二维）：
| | 高唤醒 | 低唤醒 |
|---|--------|--------|
| 负面 | 愤怒/崩溃/惊恐（→ 第 11 层 outburst） | 消沉/疲惫/无奈（→ 陪伴式回应，别吵） |
| 正面 | 兴奋/激动（→ 可跟着放开） | 平静/满足（→ 正常交流） |

**判定规则**：感叹号数（≥2）+ 情绪词强度级（崩溃>难过，分强度档）+ 语气词（太/真/好）+ 重复字（啊啊/呜呜）
**服务对象**：
- 情绪轴细分（negative 分 high/low）
- 第 11 层 outburst = 负面高唤醒（直接作为场景判定输入）
- 第 10 层沉默/消沉 = 负面低唤醒 + 短回应

## 2. 架构

### 2.1 检测器位置：`pipeline/intent.py` 扩充

```python
analyze_intent(text) → {
  "emotion": ...,        # 已有（负/正/中性）→ S6 扩展为 {valence, arousal} 或附 arousal 字段
  "needs": {...},        # 已有（info/affection/action）
  "kind": ...,           # 已有（test/approval/comfort/retreat/info）
  "scenes": {...},       # 新增：5 个场景标签，0~1 隶属度
  "situations": {...},   # 新增：9 个激活情境，0~1 隶属度
}
```

`web/app.py:925` 调用点零改动（返回 dict 多两个键，注入 think 时多渲染两段）。

### 2.2 三层结构（优先级总则的代码化）

```
性格（稳定）→ 情绪（波动）→ 场景（即时）
```

- C1~C4 裁定在代码层落为约束：场景/情境**只改表达、不改策略选择**；情绪轴**门控**特质激活

## 3. 场景标签（服务 7~11 层）

| 标签 | 判定规则 | 信号词示例（铺开版，15+） |
|------|---------|--------------------------|
| `conflict` 冲突 | 反驳句式 + 否定词紧跟判断 | 我不同意/你说得不对/你错了/但是/可是/恰恰相反/不见得/未必/不敢苟同/你这么说不对/道理不是这样/我看未必/这不对吧/你太绝对了/不能这么说 |
| `humor_offer` 对方开玩笑 | 调侃词 + emotion 非负面 | 您也有不会的/逗您玩/开玩笑/调侃/您老/老顽固/哈哈/嘻嘻/您也会错/逮着您了 |
| `refuse_request` 过分要求 | 越权请求动词 | 帮我骂/替我出气/帮我教训/帮我整/帮我写/替我编/帮我查/帮我删/帮我转账/帮我撒谎/帮我瞒/帮我骗 |
| `silence` 文本敷衍 | 短回应无新信息 | 嗯/哦/好/嗯嗯/哦哦/行/。。/…/嗯…/哈/是哦/好的/知道了 |
| `outburst` 情绪爆发 | 情绪词密度高(≥3) + 感叹号(≥2) + 长句 | 崩溃/气死了/大哭/受不了/凭什么/凭什么啊/太欺负人/我不行了/绝望了/杀了我吧/呜呜呜/啊啊啊 |

## 4. 激活情境（服务性格层）

| 情境 | 判定规则 | 信号词示例（铺开版） |
|------|---------|---------------------|
| 空谈 | 抽象词密集无实例 | 道理我都懂/理论上/原则上/说白了/本质/宏观/战略上/说起来/空谈/纸上谈兵 |
| 纠结细节 | 细节词+反复 | 但是细节/具体到/然而/可问题是/这个细节/那一步/那个环节/具体怎么 |
| 迷茫求方向 | 方向/选择词 | 我该往哪走/选哪个/不知道怎么办/方向/出路/接下来/以后怎么办/怎么选择 |
| 闲聊/拘谨 | 短句+无需求+敬语 | （兜底：无需求且场景标签全 0）|
| 越线/立场 | 立场词+冒犯词 | 你不对/你的路线错了/你那套过时了/你当年/批评你/你错了/你这是/你怎么能 |
| 传道授业 | 请教句式+概念词 | 您讲讲/这道理/怎么理解/解释一下/为什么这么说/说给我听/教教我 |
| 轻松 | emotion 非负面+闲聊 | 复用情绪轴（非负面即可） |
| 悲观 | 悲观词+否定未来 | 没希望/完了/白干了/到头来/有什么用/没意思/算了吧/认命了 |
| 深夜/深谈 | 场景注入 | 由 session 场景状态提供（time 字段/深度标记），非纯文本 |

## 5. 接口：与 C5 合流

```
app.py: intent = analyze_intent(msg)  # 多了 scenes/situations
       → think.jinja2 新增注入：
           - 场景标签（scenes）→ 7~11 层策略提示
           - 激活情境（situations）→ 选 1~2 个特质
       → think 输出"本轮激活特质"（≤2，C6 限频）
       → speak.jinja2 新增接收：
           - 场景约束（7~11 层规则按场景注入）
           - 特质约束（激活特质 → 表达方式，无例句库 C6）
```

## 6. 冷场挂起（idle 配套，并入本轮）

**问题**：现有 `app.js` 30s 冷场后每 30s 换一条 idle 动作（无限循环），用户思考/离开时显得"AI 傻"。

**改法**（`web/static/app.js` + `web/app.py`）：
| 项 | 现状 | 改为 |
|----|------|------|
| 30s 后动作 | 每 30s 换一条，无限 | **只发 1 条确认动作，然后挂起** |
| `refreshIdleAction` | 无限循环 | 删除/改为不再重排 |
| 场景建议 | 8min（16 次 idleCount）触发 | 纯计时 4min 直接触发（不依赖 idleCount） |
| 离开预警 | 8min/10min | 保留不变 |
| 用户回应 | resetIdleTimer 全复位 | 不变（挂起自然解除） |

**挂起语义**：沉默可能是思考/离开——首次确认（1 条）后静默，不骚扰；低频兜底（4min 场景建议、8min 离开预警）保留。

## 7. 信号词库规模

**铺开版**：每场景/情境 15+ 信号词（上表已示例）。与现有情绪词库（~30 词）同规格但更全。
- 注意：词库误报风险 → 复用现有 `_has_neg_prefix` 否定过滤（如"不是吧"不误杀 conflict）
- 测试：沿用 unittest（`tests/test_intent.py` 扩充场景/情境用例）
