AI店长 · 产品架构与决策框架

什么不能动 · 什么可以改 · 怎么判断

核心原则：能改的是客户要的功能，不能改的是服务客户的标准。

一、双层架构：核心引擎层 + 适配层

🔧 适配层 — 可以改，按客户需求定制

每个门店接入时根据实际情况调整。不改核心逻辑，只改表现和对接方式。

📋 课表数据格式
Excel / 飞书 / API / 手动录入 — 什么格式进来都行，统一处理后入库
📱 企微菜单配置
每家店的快捷菜单可以不同。A 馆主打约课、B 馆主打素材
🏷️ 课程命名体系
空中瑜伽 / Aerial Yoga / 反重力 — 客户叫什么，系统就认什么
👤 教练权限分级
哪些教练能看客户数据、哪些只能发素材 — 馆主自己定
📊 看板指标选择
重点看满课率还是续费率还是新客转化 — 馆主自己选
💬 话术风格
正式/活泼/佛系 — AI 的文案风格可配置
▼ 适配层依赖核心引擎 ▼

🏛️ 核心引擎层 — 不能动，动了就不是 AI店长 了

这是产品的骨架。改了其中任何一项，整个系统的逻辑就崩了。

🔄 数据飞轮逻辑
门店数据 → AI分析 → 对内管理+对外获客 → 新数据 → 飞轮再转。这是产品的基因，不可替换
📐 开源+节流双引擎
所有功能必须同时服务"增收"和"降本"两端。不能偏废。只开源不节流的工具不是AI店长
🔗 教练-店长-学员三端闭环
教练操作→店长可见→学员受益。任何一端断开，闭环失效
🧠 决策日志机制
每次AI操作（约课/推送/生成）都记录决策过程。可追溯、可复盘、可优化。这是"越用越聪明"的基础
⚡ 消息驱动架构
教练发一条消息触发整个流程链。不是"教练点按钮→系统执行"—是"教练说话→系统理解→系统执行"
📊 飞轮数据闭环
每一次内容发布、每一次客户触达、每一次约课行为都流回数据池，成为下一轮AI分析的输入

二、决策框架：遇到客户需求怎么判断

场景处理方式归属层
"我们的课不叫普拉提，叫核心床" 适配层 — 加一个课程名称映射 可改
"能不能不通过企微，改短信通知学员" 核心引擎 — 拒绝。消息驱动架构不可替换。企微是教练入口，改了入口整个产品逻辑要重做 不能改
"我们想加一个员工考勤打卡" 适配层 — 可以加，但要判断是否服务"开源节流"。如果不服务，建议客户用其他工具 可讨论
"能不能只给我素材生成，不要约课" 核心引擎 — 拒绝。只给素材就断了闭环，数据回不来，飞轮不转。这不是功能取舍，是产品逻辑取舍 不能改
"我们的教练用英文名，不是中文名" 适配层 — 改配置即可 可改
"能不能直接帮学员自动续费扣款" 核心引擎 — 不能。涉及资金操作且不可逆，不在产品边界内。系统提醒人做决策，不是替人做决策 不能改
判断口诀：动了数据飞轮 → 不能改。动了消息入口 → 不能改。动了教练-店长-学员闭环 → 不能改。
改的是表现形式、数据格式、对接方式 → 都可以改。

三、五条服务标准

不管多少家客户、不管定制多复杂，以下五条不因客户规模、付费金额、关系远近而改变。

标准 1 数据归门店，不归AI店长

任何一家门店的课表、客户、经营数据，所有权都是门店的。AI店长只是读取和分析。门店退出时数据可完整导出。不用我们的系统了，数据还是你的。

标准 2 AI建议，人做决策

系统可以做排课建议、续费提醒、素材生成，但最终拍板的永远是人。我们不做自动扣款、不做自动群发、不做"AI替你决定"。

标准 3 24小时内响应

任何客户反馈——bug、功能需求、建议——24小时内有回复。解决时间看复杂度，但至少让对方知道"听到了、在处理"。

标准 4 不卖功能，只解决经营问题

客户说"我要加一个XX功能"时，先问"你想解决什么经营问题"。如果XX功能不服务开源节流，我们会建议更好的方式。不是客户要什么都做。

标准 5 每个迭代必须有客户声音

任何新功能上线前，至少有一家真实门店确认"我需要这个"。不做拍脑袋的功能。不做"我觉得好但没人要"的功能。

四、一句话总结这个框架

核心引擎是产品的心脏，适配层是产品的皮肤。
心脏不换，皮肤可以换。标准不变，做法可以变。

动心脏的不是定制，是另一个产品。动标准的不是灵活，是妥协。
