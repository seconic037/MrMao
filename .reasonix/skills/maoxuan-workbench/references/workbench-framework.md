# 毛选工作台字段框架

这个文件给 `maoxuan-workbench` 提供详细字段解释，避免主技能文件过长。

## 一、输入采集字段

### 0. 项目名 / 主目标 / 路线

- `项目名`：给这个台账起一个稳定名字，方便后续继续推进。
- `主目标`：一个项目只围绕一个主目标，支线目标可以写，但不能抢主线。
- `目标类型`：例如职业选择、AI 落地、组织治理、流程优化。
- `路线偏好`：稳扎稳打、主动突破、保守防御，或未确定。

建议：
- 一个项目只保留一个主目标。
- 如果用户同时有“读博选择”“城市发展”“副业探索”三个目标，默认先判断哪个是主线，剩下作为支线或拆成新项目。

### 1. 我要解决的问题

- 用一句话写目标。
- 最好是“在什么时间内，把什么问题推进到什么状态”。

示例：
- 三个月内完成 AI 产品从验证到第一批付费。
- 在当前组织冲突下，重新建立单线程推进机制。

### 2. 时间尺度

建议固定使用下面 5 个刻度：
- 7天：快速动作
- 30天：阶段启动
- 90天：结果验证
- 1年：能力成型
- 5年：结构性胜负

### 3. 当前阶段

建议用这 5 类：
- 起步
- 相持
- 攻坚
- 扩张
- 调整

### 4. 当前最卡的 3 个问题

要求：
- 不要写成口号。
- 要写具体卡点。
- 后续用来判断主要矛盾。

### 5. 敌 / 友 / 可争取力量

这里不是政治判断，而是工作判断：
- 敌：当前主要阻力
- 友：稳定助力
- 可争取力量：中间地带、潜在支持者、可借资源

### 6. 客观3

默认拆分如下：
- 趋势：大势是否顺风
- 资源：钱、人、时间、渠道、品牌、技术
- 约束：政策、竞争、时点、组织、认知惯性

### 7. 主观2

默认拆分如下：
- 判断：看清主要矛盾、阶段和路线的能力
- 组织执行：调动人、拆动作、盯结果、复盘纠偏的能力

## 二、主要矛盾分析模板

建议输出为：

```markdown

- 哪些条件会让它发生转化：

```

## 六、续写旧项目规则

如果用户不是新建项目，而是继续上次项目，建议先补这 4 项：

```markdown
1. 上次结论：
2. 这次最新进展：
3. 哪些客观事实发生了变化：
4. 哪些旧判断要修正：
```

输出时要形成一条新的 `台账记录`，至少包含：
- 时间
- 最新进展
- 新判断
- 新风险
- 新动作
- 要修正的旧判断

不要直接覆盖旧记录，要保留演变过程。

## 七、HTML 分层规则

建议把 HTML 分成两类：

### 总入口 HTML

用途：
- 教用户如何使用 skill
- 放历史项目链接
- 说明输入必须在 CLI / Codex 对话中完成
- 提醒用户一次围绕一个主目标
- 提醒用户提供足够背景和客观事实

总入口不承担复杂录入和编辑。

### 项目级 HTML

用途：
- 展示单个项目的分析结果
- 展示路线、看板、五年计划、思想动态、行动指南
- 保存项目台账演变

每个主目标对应一个项目级 HTML。多个目标就拆多个 HTML。

推荐呈现：
- 桌面端采用左侧导航、右侧正文，比例约 `20% : 80%`。
- 左侧导航跟随滚动自动聚焦当前模块，帮助用户复盘时快速定位。
- 左侧导航顶部放 `返回总入口` 链接，并用不同背景色强调，用来回到教程和历史项目列表。
- 正文底部增加行动路线图或行动思维导图，把近期动作和长期目标串成一条线。
- 行动指南使用小标题、粗体关键词、标签化字段，突出动作、目的、验证、毛选执行标准、KPI 关系。
- 页面底部保留原始输入记录，作为以后续写和纠偏的依据。

## 八、举措生成规则

举措不能只是“加强”“重视”“提高”这种空话。

至少要带出：
- 动作
- 对象
- 时限
- 验证方式

如果是正式行动指南，再额外补两项：
- 毛选执行标准
- 与 KPI 或组织结果的关系

推荐统一用下面模板：

```markdown
- 动作：
- 目的：
- 验证：
- 毛选执行标准：
- 与 KPI 或组织结果的关系：
```

## 九、毛选执行标准映射

下面这张表专门用来帮助把“动作”映射回毛选工作法，避免只写管理学空话。

| 执行标准 | 何时使用 | 写法提示 |
|---|---|---|
| 实事求是 | 需要从概念回到真实指标、真实约束时 | 写清事实、指标、约束，不从愿望出发 |
| 抓主要矛盾 | 需要聚焦少数关键战点时 | 说明为什么先做这件事、其他事为何后置 |
| 调查研究 | 需要补一手信息、摸清现状时 | 写清调研对象、样本、要验证的问题 |
| 群众路线 | 需要吸收一线反馈形成方案时 | 写清如何从一线收集，再如何集中提炼 |
| 统一战线 | 需要拉通多方资源时 | 写清要团结哪些人，他们为什么会支持 |
| 试点推进 | 需要先做样板再复制时 | 写清为什么先小范围试点 |
| 集中兵力 | 资源有限、不能多线作战时 | 写清为什么只打 1 到 2 个点 |
| 复盘纠偏 | 需要按阶段校正路线时 | 写清复盘频率、复盘输出和修正动作 |
| 不打无准备之仗 | 需要前置扫雷和准备时 | 写清前置依赖、放行条件和风险清单 |
| 从个别到一般 | 首战后准备复制时 | 写清如何把个案沉淀成方法 |
| 星星之火可以燎原 | 单点突破可撬动全局时 | 写清这个样板为什么值得先点燃 |

## 十、动作示例

示例 1：

```markdown
- 动作：列出读博机会质量清单
- 目的：停止泛化问“能不能去”，改成判断这个机会值不值得去
- 验证：导师、企业、课题、毕业要求、补贴收入、就业出口六项都有明确答案
- 毛选执行标准：实事求是 + 抓主要矛盾 + 集中兵力
- 与 KPI 或组织结果的关系：降低重大职业选择的误判成本，提升长期选择权
```

示例 2：

```markdown
- 动作：访谈导师、企业侧负责人和在读学生
- 目的：从评论区意见转到一手事实
- 验证：至少问到导师或招生老师、在读博士、企业侧或毕业生各 1 人
- 毛选执行标准：调查研究 + 实事求是 + 不打无准备之仗
- 与 KPI 或组织结果的关系：帮助判断读博是否能换来真实能力和平台
```

示例：
- 调研 10 个一线用户，确认他们真正卡住的是部署成本而不是模型效果。
- 先在一个最容易出成绩的小组试点，2 周内验证流程是否跑通。
- 把当前 8 个项目砍到 3 个，只保留与主要矛盾直接相关的动作。
